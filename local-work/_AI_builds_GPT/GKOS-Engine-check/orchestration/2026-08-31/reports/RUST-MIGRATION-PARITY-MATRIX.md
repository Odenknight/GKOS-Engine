## 6. Host, platform and provider limits

- Current TS optional local embedding loader is **Linux-only**, requires trusted root-owned/non-writable ancestry, fixed384-dimensional MiniLM model identity, transformers3.7.6 runtime, required model files and SHA checks, no remote model loading. [Loader](https://github.com/Odenknight/GKOS-Engine/blob/8207958047b3361ae21ac07c5a2abbd26a42a684/src/service/local-embedding.ts#L29). It is actual model-loading work, not a portable neutral Rust adapter or proof of every r4 model-pack condition. No live model was run in this audit. Keep its good hash/offline controls while separately deciding neutrality/runtime/platform contracts.
- TS service currently defaults loopback; host/runtime identity differs from abstract generated durable identity fixture packs. Do not equate a fixture operation with a shipped administration API. The registry defers identity/credential administration, governance append and MCP effect execution; r4's broad minimum-tool prose does not override those ratified boundaries.
- FX declares cooperative-vault path protection and directoryFlush:false. Neither a Rust API change nor a passing simulated crash proves power-loss directory-entry durability. OS-specific secure traversal/fsync/locking and actual clean-machine tests remain explicit.
- Two current TS defects are conditional synthetic host-mutation gaps: stale refs accepted by assess/validate/lineage after same-generation content change, and temporal continuation skipping after same-generation removal. Root reproduced them; no live incident/new-regression claim. Fix then freeze expected behavior, not faulty results as desired parity.
- Current Lite quick-connect MCP snippets target a pinned GET-only sidecar; L21 corrects this to REST. Packaging has separate npm and native sidecar pins. A crate test pass cannot replace exact product route/manifest verification.
- Benchmark404 means no independent performance/quality baseline. FTS5 tests and self-owned24-query evaluation can be labelled non-independent controls only. Client90s/584-row traversal is bridge-inclusive wall time, not Engine execution latency.

## 8. Marshal exclusion and ownership invariants

Marshal is **not** the Rust destination or interchangeable canonical library. Separate audit pins Marshal main `a5f1d0d6975e25748d72d073cfb61858bc93297a`; its strict MARSHAL-CBOR-1 forbids floats, uses its own EVD-002 hash domain and Python ABI, and grants no GKOS engine authority. Its private/source-restricted license is not a permission to transplant code into public GKOS. [Distinct canonical profile](https://github.com/Odenknight/theMarshal-Core-Rust/blob/a5f1d0d6975e25748d72d073cfb61858bc93297a/specifications/MARSHAL-CBOR-1.md), [non-appointment](https://github.com/Odenknight/theMarshal-Core-Rust/blob/a5f1d0d6975e25748d72d073cfb61858bc93297a/crates/marshal-core-authority/src/lib.rs#L49). Any future provider/consumer relationship requires separately ratified contract, license, exact pin and authority boundaries.

Full owns all target semantic crates and the single canonical contract/fixture copy. Lite compiles the exact same crates and contract versions with projection-only product policy; it does not copy a parser, frozen contract pack, retrieval policy, CBOR implementation or authority resolver into its repository. Retrieval/nav never import effects; nav stays core-types-only; context composes eligibility→rank→closure; service owns host state and exposes only approved transport operations. Reuse preserves evidence; it does not preserve the old two-owner architecture.

See [verified audit](AUDIT-ENGINE-LITE-BENCHMARK.md) and [source/test ledger](engine-lite-source-test-ledger.json) for commands, exact open-PR coordinates and access limits. No additional tests, normative ratifications or release approvals are asserted by this mapping.
