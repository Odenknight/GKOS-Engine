## Why

Two independent build teams were pushing to this repo in the same window
today (a known, tracked situation — see repo maintenance notes). The v1.1.2
tag got taken by the other run before this run could land its fixes, so this
run's work is tagged v1.1.3 instead to avoid collision. The underlying fixes
are about keeping macOS Single Executable builds correct across Intel/Apple
Silicon runner combinations, and making sure the documented sensitivity
default matches what the code has actually done since v1.0.6 (fail closed to
`secret`, not `internal`, when a note's sensitivity is unset).

## Feature/functionality state now (v1.1.3)

- **CLI**: `okf` (bin: `bin/okf.mjs`) — the OKF23 projection/graph engine's
  command-line entry point.
- **Fail-closed sensitivity**: any note lacking an explicit `sensitivity`
  field is treated as `secret` (the most restrictive level), not a mid-open
  default. This has been true since v1.0.6 and is now documented accurately.
- **Twelve-state epistemic vocabulary** (GKOS v0.76-aligned): out-of-vocabulary
  `epistemic_state` values project to `unknown` (null-weight) with a
  machine-detectable `effective.epistemicStateDefaulted` marker; the original
  invalid value is preserved and flagged.
- **Intelligence contract (`gkos.intelligence.v1`)**: an optional, offline-safe
  loopback DSPy/Python sidecar can propose patches — validated deterministically,
  restricted-field, raise-only-sensitivity, no write/approval power of its own.
  The engine runs fully deterministically with the sidecar absent.
- **SEA (single-executable) distribution**: `kosmos-agent` binaries are built
  and code-signed per platform/arch (macOS Intel + arm64, Windows), each
  checksummed against the official Node.js release before packaging.
