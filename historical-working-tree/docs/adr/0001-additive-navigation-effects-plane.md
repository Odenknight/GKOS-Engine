# ADR 0001: Additive Navigation Effects plane

- Status: Accepted for implementation
- Date: 2026-08-20
- Release target: GKOS-Engine 2.2.0 feature line
- Contract: Navigation Effects 1.0.0

## Context

Navigation 1.0 is deterministic, source-content read-only, and protected by a
transitive import-graph purity test. Near-real-time managed-MOC maintenance and
credential-bound agent note writes require filesystem effects, durable intent,
recovery, and explicit authority. Treating those effects as an extension of the
existing Navigation API would make its capability claims untrue and break
read-only consumers.

Filesystem watcher events are delivery hints. They may be delayed, coalesced,
or lost. Correctness must come from hash-bound intent and reconciliation rather
than event delivery.

## Decision

Add a separately versioned, opt-in `navigation-effects` plane. The Engine owns
deterministic effect values, validation rules, canonical receipts, recovery
classifications, and host-adapter contracts. Host products own authority,
secrets, user confirmation, filesystem execution, event delivery, and UI.

`src/navigation/**` remains unchanged and may not import the effects plane or a
filesystem module. `getNavigationCapabilities()` remains unchanged. The new
`getNavigationEffectsCapabilities()` reports planning separately from active
execution dependencies. The mere presence of implementation code never makes a
write capability true.

Every eventual effect must bind actor, grant, scope, policy, target, prior
digest or required absence, proposed digest, configuration, corpus,
idempotency key, journal sequence, and receipt. Existing MOCs are unmanaged by
default. Region-managed files replace only the versioned generated region;
fully managed files require an adopted hash binding. Any marker ambiguity or
precondition mismatch fails closed.

The marker grammar for contract 1.0 is:

```text
<!-- gkos:moc generated:start version=1 config=sha256:<64 lowercase hex> -->
<generated bytes>
<!-- gkos:moc generated:end -->
```

There must be exactly one unnested start/end pair, in that order. The adopted
binding records offsets and the generated body digest. Missing, duplicate,
nested, malformed, moved, or configuration-mismatched markers require review.

Archives remain under `_archive/moc-runs/YYYY-MM-DD/<run-id>/` and retain the
existing exact Navigation exclusion. Operational journal and registry state
belongs under ignored `.gkx/`; plaintext credentials never do.

Agent authority binds a credential identifier to a stable lowercase UUIDv7 and
a normalized vault-relative root. The display name is metadata only. Defaults
deny deletion, arbitrary paths, cross-agent writes, MOC direct writes,
sensitivity lowering, promotion, approval, and supersession.

## Consequences

Read-only consumers require no migration. Effects consumers must explicitly
configure a host adapter, authority provider, durable journal, and policy before apply
or agent-write capabilities become true. Archive or journal corruption blocks
writes. Crash recovery and cross-platform filesystem semantics become release
gates for later phases.

Phase 0 introduced no executor and performed no source-content effect. After
contract approval, Phases 1–2 add a deterministic planner and an optional Node
executor under a separate package subpath. Merely installing that executor does
not make any capability true; the host must still configure and report the
required adapter, authority provider, journal, and policy.

This decision is integration-only and makes no GKOS conformance claim. Any
normative provenance or receipt change belongs in a separate gkos-standard
proposal.
